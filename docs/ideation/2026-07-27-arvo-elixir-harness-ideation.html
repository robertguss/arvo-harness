Grounding Context

Codebase context

Arvo is the Elixir/BEAM twin of Rust Ore: OTP app with pure Arvo.Agent.run/3, Session GenServer (JSONL tree under ~/.arvo/sessions/), TUI GenServer mode: :raw_v0, line Arvo.Repl, Plugin/Profile set-diff, core tools Read/Bash/Edit/Write via jido, flagship fff (Rustler), xAI auth + completion.

Gaps that dominate grounding: product chat path calls Agent.run directly (Esc/steering second-class); completion hardcodes non-stream Req.post to xAI despite ADR-0002/req_llm; tip-only resume on a parent_id tree with no rewind API; skills/hooks/commands under-wired; docs lag (README Pre-code, SPEC.md missing).

Past learnings

ADR-0001: BEAM is curriculum (OTP, live profile load, process-per-agent open). ADR-0002: own experimental seams only—wrap tools, consume req_llm types for providers. Profile is the product unit; observe-only hooks; philosophy refusals are design constraints (no MCP/plan/todo/permission rails; Esc is the brake). Ore post-v0.1 ideation ranked continuity → profile completeness → providers → memory; import lessons, exploit BEAM where Ore paid Rust tax.

External context

Crowded TS/Go/Rust TUI category. Closest philosophy peer: Pi (tiny core, JSONL session trees, extensions, multi-mode). Goose Recipes ≈ named Profiles. agentskills.io progressive disclosure is cross-tool standard. Loom/Jido show BEAM agent stacks. Scarce edge: personal BEAM harness that stays small—OTP concurrency + named Profiles, not Claude Code feature parity.

1.

One turn owner: Esc is real on the product path

Agent loop & concurrency Conf 92% Complexity Medium

Every interactive chat turn must be owned by Session.start_turn (supervised Task, steering drain, cancel_turn / :brutal_kill). Delete the product path where Arvo.Repl.run_chat calls Arvo.Agent.run on the REPL process. Pure Agent.run remains the library core for tests and headless injectors—but bin/arvo never bypasses Session. Pair with a killable input owner (raw terminal or TUI key path) so Esc can fire while a turn is running, not only between IO.gets prompts.

Illustrative: dual drivers collapse so Esc, steering, and cancel-survives attach to the path users actually run.

Basis
direct: arvo/lib/arvo/repl.ex product chat invokes Arvo.Agent.run inline; Session owns start_turn/cancel_turn/turn_task and tests prove kill-survives-session—but only on that path. TUI Esc → Session.cancel_turn while Repl is blocked in completion.
Rationale
Philosophy’s single brake is Esc. Until product path and cancel path are the same path, every UX claim about mid-turn steering and supervised turns is true only in tests. This is the unlock for continuity, streaming cancel feel, and multi-surface.
Downsides
Repl becomes thinner; tests that assumed direct Agent.run need rewiring; raw-mode input is extra work beyond “just call start_turn.”
2.

Navigable workshop memory

Session continuity Conf 90% Complexity High

Treat the JSONL store as a navigable DAG product, not a linear chat log with accidental parent_ids. Ship four primitives together: explicit HEAD (not tip = last file line); fork/rewind that only appends and moves HEAD; cancel-as-fork (Esc leaves a cancel leaf and preserves last good parent); and JSONL as process of record so resume rehydrates messages, cumulative tokens, model, and active profile from the log—Session GenServer is a disposable open-handle cache.

Illustrative: append-only tree with a movable HEAD makes Esc, retry, and compact into first-class navigation.

Basis
direct: Store already appends {id, parent_id} and rebuilds via messages_to_tip; resume uses List.last(entries) only; no rewind/branch/last_surface API; resume reloads history but not tokens. external: Pi JSONL session trees; chess/PGN variation boards. Continuity was the top scarce Ore bet.
Rationale
Continuity without navigable history is crash durability. The tree investment only pays when HEAD is choosable and durable state is reconstructed from disk—the scarce daily-driver trust surface.
Downsides
Largest surface area of the set; UX for node pick matters; compaction nodes must become navigable fork points carefully so users don’t lose the “kept” window story.
3.

Profile becomes the product

Profiles & plugins Conf 88% Complexity Medium

Finish the Profile coinage as one shippable unit: wire remaining manifest consumers (progressive skills name+desc until Read, namespaced plugin slash, observe-only hooks on the event bus); expand profile TOML from plugin set-diff to a runtime constitution (default model, max_turns, compaction window, skill allowlist, visible core tools); and treat profile packages under ~/.arvo/profiles/ as the shareable artifact (Goose Recipes class, no MCP-in-core). Activation remains set-diff under always-on base; trust stays on project plugin dirs only.

Basis
direct: Manifest normalizes tools/skills/children/commands/hooks; Registry activates tools + OTP children only; Repl context often omits :skills so build_system sees []; TUI slash is a closed core set. CONTEXT.md: Profile is why the plugin seam exists. external: Goose Recipes; agentskills.io progressive disclosure; Pi packages.
Rationale
Without skills+slash+hooks on the wire, Profile is a tool-pack swap. Completing consumers once multiplies every future plugin; constitution fields make /profile rust a trustworthy mode switch without plan mode or permission rails.
Downsides
Constitution fields tempt config sprawl; package format needs a minimal schema so Ore twin experiments stay aligned without premature marketplace energy.
4.

Finish ADR-0002: real streaming completion

Providers & completion Conf 91% Complexity Medium

Delete the hand-rolled chat_via_http path that hardcodes api.x.ai with stream: false and post-hoc full-body on_delta. Default complete_fun consumes req_llm streaming types; Registry (prefix, base_url, auth via TokenManager) becomes the mount plate. No second Provider behaviour—finish the asymmetric design already chosen. Real chunk deltas unlock honest TUI chrome and make Esc meaningful mid-model, not only after a 120s receive timeout.

Basis
direct: ADR-0002 (core speaks req_llm types; harness owns registry/auth/selection only); mix depends on req_llm but no live ReqLLM. call sites in completion; Registry base_url unused by Completion; product tests encode current non-stream behavior.
Rationale
One deletion collapses fake streaming, dead registry fields, and double-normalizer risk. Multi-provider later is a side effect of finishing the mount—not a marketplace race.
Downsides
req_llm streaming edge cases and tool-call deltas need careful event mapping; temporary breakage of product_path tests that freeze current strings.
5.

Event-first multi-surface

TUI & interaction Conf 78% Complexity Medium–High

Freeze a small versioned event schema emitted only from Session/Agent (turn start, deltas, tool start/end, usage, cancel, compact). Every surface is a pure projector: line Repl printer, ambient “flight strip” chrome (model/profile/tokens/tool), headless NDJSON, later cell-diff painter, iex. Make an explicit product decision that BEAM differentiates on process events and cancel semantics—not on racing Charm/OpenCode paint. “Polished” means zero missing events and honest cancel chrome first; renderer investment is optional forever.

Basis
direct: TUI GenServer already claims event-derived state but Repl dual-writes IO.write deltas; mode: :raw_v0; mix.exs has no TUI renderer dep; ADR-0001 accepted hand-rolled differential cost. Scarce external bet: headless event bus. Philosophy: no dialogs; Esc is brake.
Rationale
Renderer upgrades stop rewriting interaction logic. Tests and CI stop scraping stdout. Multi-surface (TUI + headless + later) compounds on one bus—the Pi four-modes idea on OTP without a Node worker split.
Downsides
Tensions with “polished TUI day one” wording; requires deliberate ADR/STRATEGY note so the zero-paint strategy is not misread as abandonment of feel.
6.

Length-error → auto-compact policy turn

Providers & completion Conf 86% Complexity Low–Medium

When completion hits context length, Session (policy outside the pure loop) runs one compact using existing compaction entry shape, then re-invokes the same user turn once. Keep /compact for intentional focus text; remove it as the only recovery path when the model already failed. Prefer a real model summarizer over the 200-character role-slice default before auto-retry, so the silent path doesn’t destroy nuance.

Basis
direct: Length error message explicitly says run /compact, no automatic retry; auto-compact exists on token threshold path only; default_summarize slices content; pure Agent invites external policy; product_path tests assert the homework message.
Rationale
Long sessions are the continuity bet; dying mid-turn with a manual, lossy compact is the sharpest daily friction. Automating once is high leverage relative to surface area.
Downsides
Bad auto-summaries can hide failure modes; need Esc still cancel mid-compact; risk of infinite compact loops if threshold mis-set (cap at one retry).
7.

Parallel pure tools under Task.Supervisor

Agent loop & concurrency Conf 84% Complexity Medium

Keep tool results sequential in the model transcript contract if needed, but execute independent pure tools (Read, search, non-mutating helpers) concurrently under a Task.Supervisor when a turn emits a multi-tool batch. Esc still brutal-kills the whole turn group. Leave write/bash serialization conservative. This is the cheapest place BEAM should feel different from Ore’s single-threaded story without inventing multi-agent chat democracy.

Basis
direct: run_tools_sequential via map_reduce; Session one-at-a-time turn_task; ADR-0001 process-per-agent openness; no worktree workers yet. Philosophy sequential tools was about cancel simplicity, not wall-clock latency as destiny.
Rationale
Multi-read/multi-search turns are common and currently serialize wall clock on a runtime built for isolation. Parallel-safe batches are curriculum payoff without MCP or permission rails.
Downsides
Ordering and error aggregation need a crisp contract; misclassifying a impure tool as pure is dangerous; TUI tool chrome must show concurrent tags honestly.
